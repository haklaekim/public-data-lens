# 차기 기능 백로그 v1.0 — 공개 배포(MCP 전용) 이후

- 상태: 초안 (2026-07-28)
- 배경: v1.0 공개 배포는 **gateway + mcp + api(정본 URI 해소)** 구성으로 확정
  (`docker-compose.prod.yml`). 웹 UI·컨시어지·REST 공개는 배포 범위에서 제외하고
  본 문서에 별도 스펙 후보로 남긴다. 설계서 v1.0은 동결 상태이므로, 아래 항목은
  부속 명세 또는 v1.1에서 다룬다(설계서 동결 원칙 준수).

## 0. 데이터 구조 관측 계층 (v2 — 최우선 후보)

- FILE 원본 컬럼·예시값 관측 제공: **탐색 → 활용 전 점검**으로 서비스 단계 상승.
- 상세 설계: [데이터구조_관측_설계_v2_초안](데이터구조_관측_설계_v2_초안.md) —
  검토안 수용·보완(수집 커버리지 정책, 라이선스 게이트, PII 통제, 판정 규칙 4종,
  `get_dataset_structure` v1.2 minor, AIRD 실측 연계). 착수 전 선행 조사 S0 필수
  (실파일 확보 경로·발췌 제공의 법적 범위).

## 1. 웹 UI 별도 서비스 (3층 재배포)

- 현 `apps/web`(React/Vite)을 별도 인프라의 독립 서비스로 배포한다.
- 웹 서비스는 자체 nginx로 정적 서빙 + REST 프록시를 구성하고, 본 스택의
  api(비공개 `/api/**`)를 내부 경로 또는 전용 노출로 소비한다.
- 결정 필요: (a) 웹 전용 api 사본을 둘지, 본 스택 api를 공유할지
  (rate limit·사용량 캡이 단일 프로세스 전제임에 유의),
  (b) 생성형 컨시어지 재개 여부와 예산 캡(월 10~20만 원 승인 범위).
- 재개 시 `ANTHROPIC_API_KEY`는 웹 쪽 스택에만 둔다 — MCP 스택은 계속 무키 운영.

## 2. REST `/api/**` 공개 계약 승격

- 현재 공개 계약은 MCP Tool 스키마 v1.0.0(동결)뿐이며 REST는 웹용 내부 API다.
- LLM 없이 프로그래밍 방식 접근 수요(스크립트·타 시스템 연동)가 확인되면
  gateway 라우팅 추가 + REST 스키마의 부속 명세 동결로 승격한다.
- 승격 전까지 gateway는 `/api/status`·`/api/resources/privacy`만 연다.

## 3. MCP 채널 사용 지표 (§12)

- 현재 MCP 트래픽은 gateway의 익명 access log(IP 미포함)로만 관측된다.
- REST와 동등한 앱 레벨 익명 사용 로그(Tool명·zero-result 여부·처리시간,
  옵트아웃 헤더 존중)를 mcp 서버에 추가해 §12 지표(0건 비율 등)를 MCP 채널에서도
  산출한다. streamable HTTP 미들웨어 또는 Tool 래퍼 계층에서 구현.

## 4. v1.0 확정 잔여 조건 (README 승계)

- 골든셋 인간 검수.
- `data.datahub.kr` 도메인 연결 완료 확인 — `BASE_URI`가 이 도메인으로 하드코딩되어
  있으므로 실제 배포 도메인과 일치해야 정본 URI 디레퍼런싱(§7)이 성립한다.

## 5. 운영 고도화

- gateway `set_real_ip_from` 다중 CIDR·IPv6 지원(현재 env 1개) —
  필요 시 템플릿에 두 번째 변수 추가 또는 conf 직접 관리로 전환.
- LB 없는 소형 배포용 gateway TLS 직접 종단(certbot) 옵션.
- healthcheck 조건 기반 기동(`depends_on: condition: service_healthy`)과
  무중단 카탈로그 교체 절차 문서화(현재는 restart로 확정).
- `get_context` 호환 Tool 제거 검토 — 주요 클라이언트의 Resource 지원 확인 후(§4.1).

## 6. 저장소 정리

- `apps.zip`(20MB, macOS 백업 사본)을 저장소에서 제거하고 필요 시 릴리스
  아카이브로 이관. 공개 저장소 전환 전에 이력 정리 여부도 결정.
