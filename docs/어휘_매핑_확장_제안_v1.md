# 어휘 매핑 확장 제안 v1 (초안) — 목록 전 항목의 무손실 의미 표현

- 상태: DRAFT (2026-07-31) — 검토·승인 후 매핑표 v1.1과 JSON-LD 확장(additive)으로 반영
- 목표: 목록개방현황의 **모든 항목**이 표준 어휘 또는 명시적 커스텀 어휘(kdp:)로 매핑되어
  JSON-LD에서 의미 손실 없이 표현되게 한다. 현재 미매핑("—") 항목 18종이 대상.

## 0. 원칙

1. **원문 보존 + 병기**: 표준 URI로 "대체"하지 않는다 — 원문 리터럴을 유지하고 표준
   URI를 병기한다(정규화는 참고, 법적 해석 아님).
2. **AIRD는 진단 계층 전용**: AIRD 어휘(aird:)는 적합성·진단(dataType, QI_MMI, DM)을
   표현하는 어휘이지 기술(descriptive) 메타데이터 어휘가 아니다. 목록 항목을 aird:로
   억지 매핑하지 않는다 — 그것이 표준의 취지에 맞다. 기술 계층은 DCAT 계열이 정본.
3. **표준에 정확한 대응어가 없으면 kdp:를 정식 어휘로**: kdp: 용어에 rdfs:label·
   rdfs:comment·(가능시) rdfs:subPropertyOf를 부여해 문서화된 어휘로 승격한다.
   "커스텀이라서 손실"이 아니라 "정의가 공개된 어휘"가 되게 한다.

## 1. 미매핑 항목의 매핑 제안 (18종)

| 원본 항목 | 정규화 필드 | 제안 매핑 | 근거·비고 |
|---|---|---|---|
| 파일데이터명 | file_data_name | **`dcat:distribution` → `dcat:Distribution`/`dct:title`** | DCAT 정석 구조로 승격. 관측 계층 SourceAsset과 1:1 — S1 관측이 있으면 관측 URI를 `dcat:accessURL` 근거로 연결 |
| 확장자(데이터포맷) | formats[] | Distribution의 **`dct:format`** + 매핑 가능 시 **`dcat:mediaType`**(IANA) | CSV→text/csv 등 사전 매핑, 원문은 dct:format 리터럴 병기 |
| 전체행 | row_count | **`dct:extent`**(rdf:value + kdp:unit "rows") 병기 + `kdp:rowCount`(정수) 유지 | 행수의 직접 표준 부재 — extent가 의미상 최근접 |
| 다운로드수 / 조회수 | download_count / view_count | **`schema:interactionStatistic`** → `schema:InteractionCounter`(`schema:DownloadAction`/`schema:ViewAction`) | schema.org가 의미 정확 일치. 스냅샷 시점 종속임을 kdp:asOf로 병기 |
| 관리부서명 / 관리부서 전화번호 | dept_name / dept_phone | **`dcat:contactPoint`** → `vcard:Organization`(`vcard:fn`, `vcard:hasTelephone`) | DCAT-AP 관례. 기관 공개 연락처(원문 공개값)이나 §10 관점 재확인 1회 필요 |
| 비용부과유무 | fee | **`schema:isAccessibleForFree`**(boolean, FREE→true/PAID→false) + `kdp:fee` 코드 유지 | UNSPECIFIED는 schema 속성 생략(3치→2치 손실 방지 위해 kdp 병기 필수) |
| 비용부과기준 | fee_basis | `kdp:feeBasis`(리터럴) | 표준 부재(ODRL 과공학) |
| 신청가능 트래픽 | traffic | `kdp:trafficLimit`(리터럴) | API 제공 조건 — 표준 부재 |
| API 유형 | api_type | **API 레코드를 `dcat:DataService`로 타입 병기** + `kdp:apiType`(REST/LINK/SOAP) | DCAT 3 정석: API는 DataService(`dcat:endpointDescription`은 S3 관측 후). LINK형은 `dcat:landingPage`만 |
| 수집 방법 | collection_method | **`dct:accrualMethod`**(리터럴) | DCT 정확 대응(수집·추가 방법) |
| 보유근거 | retention_basis | **`dct:provenance`** → `dct:ProvenanceStatement`(리터럴) | 법령·근거 서술의 관례적 자리(DCAT-AP). 심화 시 ELI URI는 후속 |
| 다음 등록 예정일 | next_registration_date | `kdp:nextRegistrationDate`(xsd:date) | 표준 부재(갱신 예정일) — update_cycle과 함께 신선도 판정 근거 |
| 매체유형 | media_type | **`dct:type`** → DCMI Type 병기(텍스트→dcmitype:Text, 이미지→StillImage, 동영상→MovingImage, 소리→Sound, 멀티미디어→InteractiveResource?) + 원문 유지 | '기타'는 원문만. 멀티미디어 대응은 검토 필요 |
| 제공형태 | provision_type | `kdp:provisionType`(리터럴) | 값이 포털 고유 관행(포털 다운로드/기관 다운로드/전자매체/LOD연계) — 표준 부재. LOD연계는 향후 `dcat:accessService` 후보 |
| 기타 유의사항 | notes | `kdp:notes`(리터럴) | dct:description과 별개 항목 — 병합하면 손실. 표준 부재 |
| 데이터 한계(기관 기재) | data_limits | **`dqv:hasQualityAnnotation`** → `dqv:QualityAnnotation`(oa:bodyValue=원문, 제공자 자기기재임을 kdp:assertedBy "provider"로) | 이미 DQV를 이슈 관찰에 사용 중 — 제공자 선언 품질 노트로 정확히 표현 |
| 국가중점여부 / 표준데이터여부 | is_national_core / is_standard | `kdp:isNationalCore` / `kdp:isStandardData`(xsd:boolean) | 국내 제도 개념 — 표준 부재. 정의를 어휘 문서에 명기 |
| 심의유형 | review_type | `kdp:reviewType`(리터럴) | 포털 내부 절차 개념 |

## 2. 기존 매핑의 값 URI 병기 (P1 백로그 통합 — 리터럴 → 표준 URI "병기")

| 필드 | 병기 제안 |
|---|---|
| update_cycle | **EU 발행처 Frequency 권위 테이블 URI**(…/authority/frequency/DAILY 등) — 코드 사전 8종 전부 대응 존재 |
| license_code | KOGL 유형별 **공식 KOGL URI** + CC 계열은 creativecommons.org URI. OTHER/UNSPECIFIED는 원문만 |
| theme_top/sub | 포털 분류체계를 **kdp SKOS ConceptScheme으로 발행**(정본 URI `/vocab/theme/…`) 후 `dcat:theme`을 URI로 병기 |
| regions[] | 이미 ISO 3166-2:KR 코드 — `dct:spatial`에 행정구역 URI(예: KR-11) 병기 |
| org_code | 행정표준코드 기관 URI 체계 확인 후 `dct:publisher`의 @id로 병기(불가 시 kdp URI) |

## 3. 반영 방식 (전부 additive — 재개봉·breaking 없음)

1. JSON-LD Context에 `schema:`·`vcard:`·`dcmitype:` 프리픽스 추가, kdp 신규 용어 매핑
2. `dataset_jsonld()` 확장: Distribution 노드(파일데이터명·포맷), DataService 타입 병기,
   위 표의 속성 추가 — 기존 키 불변, **jsonld 뷰 required 키 불변**(계약 v1.4 minor 불필요
   가능성 높음 — 스키마상 dataset은 open object. 검증 후 판단)
3. **kdp 어휘 문서 발행**: `/projects/datanav/ns/kdp` 정본 URI가 용어 정의(rdfs:label·
   comment·정의 출처)를 반환하게 — "커스텀 어휘의 문서화" 완성
4. SHACL 셰이프 확장 + rdflib 무손실 검증(트리플 수 회귀 테스트)
5. 매핑표 v1.1 갱신("—" 소거) — 모든 항목이 매핑 열을 갖게 됨

## 4. 결정 필요 (사용자)

- D1. 관리부서명·전화의 vcard 공개 매핑 — 기관 공개 연락처이나 §10 관점 확인
- D2. theme SKOS 스킴을 우리가 발행하는 방식(kdp 네임스페이스) 동의 여부
- D3. 매체유형 '멀티미디어'의 DCMI 대응(InteractiveResource vs 생략) 등 코드 사전 세부
