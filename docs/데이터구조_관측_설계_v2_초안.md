# 데이터 구조 관측 계층 설계 v2.2 (초안 — 조건부 승인 반영)

- 상태: DRAFT v2.2 (2026-07-29) — 3차 검토 "조건부 승인"의 필수 4건+보완 4건 반영
- 위상: 설계서 v1.0(동결)의 **확장 계층** — 3층 구조·책임 분리(§2)·식별자 체계(§7)를
  변경하지 않으며, 계약은 부속 명세 semver(minor)로 처리한다. **재개봉 불필요.**
- 선행 관계: v1.0 공개 배포(MCP 스택)와 독립 — 배포를 차단하지 않는 별도 트랙
- 개정 이력: v2 → v2.1(2차 검토 15건 반영) → v2.2(3차 검토 반영: 레코드/자산 상태 분리,
  테이블 단위 관측 범위, 불변성 충돌 해소, 테스트 기준선 실측·수정, example_status,
  샘플링 키 안정화, 안전검사 선행 저장, 수치 출처 명시). 판정표는 §0.1·§0.2 참조

## 1. 목표와 비목표

**목표** — 사용자가 포털에서 파일을 내려받기 전에 답할 수 있게 한다:
"이 데이터에 필요한 컬럼이 실제로 존재하고, 값이 예상한 형식인가?"

**비목표(명시적으로 하지 않음)** — 컬럼 의미 동일성 판정, 실제 조인 가능성 판정,
전체 데이터 품질 평가, 컬럼 정규화·표준 매핑(후속 별도 계층).

**근거 수준 사다리 확장**: `CATALOG_METADATA_ONLY`(현행) → **`FILE_OBSERVATION`**(신규,
파일 구조·예시값 범위 — scan_scope로 FULL/PARTIAL 강도 구분) → `API_RESPONSE_SAMPLE`(3차).
신규 수준은 **신규 표면에만** 쓰며 기존 응답의 evidenceLevel은 불변.

## 3. 데이터 모델 (v2.1 개정 — 필수 지적 1·2·3·5·6·8·9 반영)

**핵심 정정**: CatalogRecord는 특정 시점의 목록 기술 레코드이지 실제 파일이 아니다.
하나의 FILE 목록에 CSV·XLSX 복수 파일, 연도별 파일, ZIP 내부 다수 파일, XLSX 다중 시트가
있을 수 있으므로 컬럼은 **실제 관측한 파일의 테이블**에 귀속한다.

```
Dataset (기존, 불변)
 └─ CatalogRecord (기존, 불변)
     ├─ RecordCoverageState (신규, 가변 1행)  ← 자산 상태의 집계(파생)
     └─ SourceAsset (신규: 실제 파일 1개 — 레코드당 복수 가능)
         ├─ AssetCoverageState (신규, 가변 1행) ← 자산별 수집 상태
         └─ StructureObservation (신규: 특정 파일 버전의 불변 관측)
             ├─ DataTable 1 (CSV 본문 / XLSX 시트 / ZIP 멤버) ← 관측 범위는 이 단위
             │   └─ FileColumn[]
             └─ DataTable 2
                 └─ FileColumn[]
```

예: "교통사고 통계" 레코드에 2024년.csv(성공)·2023년.xlsx(실패)·코드표.zip(보류)가
있으면 자산 상태는 각각 기록되고 레코드 상태는 **PARTIAL**로 집계된다.

관측 스토어는 카탈로그 릴리스와 분리한다(`data/observations/observations.db`).
월간 목록 스냅샷과 파일 관측은 주기·수명이 다르며, 연결 키는 (목록키, list_type)이다.

### RecordCoverageState (가변 — 자산 상태의 집계, 저장 또는 뷰)
```
record_id, list_key, list_type
coverage_status        NOT_COLLECTED | QUEUED | COLLECTING | AVAILABLE | PARTIAL
                       | SOURCE_UNAVAILABLE | UNSUPPORTED_FORMAT | ACCESS_RESTRICTED
                       | COLLECTION_FAILED | API_STRUCTURE_NOT_SUPPORTED_YET
available_asset_count / total_asset_count
portal_url             공개 포털 상세 페이지
```
집계 규칙: 전 자산 성공 → AVAILABLE, 일부 성공 → PARTIAL, 전부 미수집 → NOT_COLLECTED 등.

### AssetCoverageState (가변 — 자산별 상태 머신, 관측이 아님)
```
asset_id
status                 (위 상태값 중 자산 수준 적용분)
failure_reason         기계 판독 코드
last_attempt_at
current_observation_id 최신 관측 참조(성공 시)
last_verified_at       동일 해시 재확인 시점 — 갱신 가능한 것은 여기뿐
```
미수집·실패는 **여기까지만** 기록된다 — 해시·컬럼 없는 "관측"은 존재하지 않는다.
(검증 이력이 필요해지면 향후 VerificationEvent 추가 — v2 범위 밖)

### SourceAsset (실제 파일)
```
asset_id               결정 ID
record_id
file_name, format      CSV | XLSX | ZIP | ...
portal_url             공개 가능 — MCP 응답 기본값
source_locator         내부 수집용 실제 위치(서명 URL·토큰 가능성) — 비공개 저장
source_locator_public  boolean — 안전 확인된 경우에만 응답 포함
```

### StructureObservation (완전 불변 — 파일을 실제 분석한 경우에만 생성)
```
observation_id   = sha256(asset_id + source_sha256 + tool_version + rule_bundle_version)
                   — 같은 파일이라도 규칙·도구가 바뀌면 새 관측
source_sha256    파일 해시(재현성 앵커)
observed_at      최초 관측 시점 — 이후 어떤 필드도 변경하지 않는다
                 (재확인 시점은 AssetCoverageState.last_verified_at — 불변성 충돌 해소)
tool_version, rule_versions
scan_scope       FULL | PARTIAL — 테이블별 범위의 집계(하나라도 PARTIAL이면 PARTIAL)
structure_hash   테이블·컬럼 구조의 해시(스키마 변경 이력의 비교 키)
license_gate     FULL | COLUMNS_ONLY (S0-2 게이트 결과)
```

### DataTable (XLSX 시트·ZIP 멤버 구분 — **관측 범위의 기준 단위**)
```
table_id, observation_id
source_path            ZIP 내부 경로(해당 시)
sheet_name             XLSX 시트명(해당 시)
table_index            파일 내 순번
scan_scope             FULL | PARTIAL      ← 시트별로 다를 수 있음(예: 요약 200행 전수,
rows_scanned                                 원자료 300만 행 중 10만 행)
row_count_observed, row_count_total(추정 가능 시)
column_count
encoding, delimiter    (CSV)
```
컬럼의 null_count·유형 판정 분모는 **소속 테이블의 rows_scanned**다.

### FileColumn
```
ordinal                원본 순서 (1-base, 테이블 내)
source_name            원본 컬럼명 — 절대 변경하지 않음
observed_type          INTEGER|NUMBER|STRING|DATE_LIKE|BOOL_LIKE|EMPTY
type_observation       { scan_scope, values_examined, non_empty_examined, rule }
example_status         AVAILABLE | NO_NON_NULL_VALUES | WITHHELD_BY_LICENSE
                       | WITHHELD_BY_SAFETY | NOT_COLLECTED | COLLECTION_FAILED
                       — 예시값 부재의 사유를 안전 상태와 분리해 명시
examples[]             example_status=AVAILABLE일 때만 제공(≤10)
example_method         HASH_BOTTOM_K_DISTINCT (§5)
null_count_observed    스캔 범위 내 결측 수 (분모 = rows_scanned)   ← 지적 5
empty_string_count_observed / placeholder_count_observed
sample_safety_status   CLEAR | MASKED | WITHHELD | REVIEW_REQUIRED | NOT_ASSESSED  ← 지적 10
safety_reason          PII | LICENSE | FREE_TEXT | TECHNICAL (WITHHELD·REVIEW 시)
format_note            제한적 관찰("YYYY-MM-DD 형태" 등) — 없을 수 있음
-- AIRD 예약(v2에서는 산출·표시하지 않음, 지적 14):
distinct_count_observed?, distinct_count_method?, parse_failure_count?
```

## 4. 관측 사실과 규칙 기반 판정의 구분 (지적 7)

> 원본 컬럼명·순서·파일 해시·포맷·관측 시점·행/컬럼 수·예시값의 원본 문자열은
> **직접 관측 사실**로 기록한다. `observed_type`, `sample_safety_status`, `format_note`,
> placeholder 추정, 라이선스 게이트 결과는 **명시된 규칙에 의해 생성된 관찰·판정**이며
> 해당 규칙 버전을 동반한다.

| ruleId | 내용 |
|---|---|
| `column-type-observation-v1.0` | 스캔 범위 기반 유형 관측 — scan_scope·분모 동반 필수 |
| `example-extraction-v1.0` | **HASH_BOTTOM_K_DISTINCT** (§5) — 첫 10행·정렬 상위 방식 금지 |
| `sample-safety-v1.0` | 위험군별 기본 처리(§7 표) — 컬럼명 사전 + 값 패턴 이중 탐지 |
| `structure-status-v1.0` | CoverageState 상태 전이 규칙 |

## 5. 예시값 추출 — 해시 bottom-k (지적 4)

```
값을 원본 문자열로 보존 → raw_value 단위 중복 제거 → 스트리밍 스캔
→ h = SHA256(asset_id + table_path + sheet_name + column_ordinal + raw_value)   # UTF-8 고정
→ (h, value) 최소 10개만 유지
```

해시 키는 **관측 ID·도구 버전과 무관**하게 파일·테이블·컬럼 위치에만 종속 —
규칙·도구가 바뀌어도 같은 파일이면 같은 예시값이 유지된다(안정성). 표시값은 원본
그대로이며 해시 계산용 바이트 인코딩만 UTF-8로 고정한다.

- 결정론적(재실행 동일), 메모리 O(10), 행 순서 독립, 사전순·크기순 편향 없음
- 전량 스캔이 전제이므로 null/empty/placeholder 카운트도 같은 패스에서 정확히 계산
- 대용량 상한(예: 500MB) 초과 시 scan_scope=PARTIAL + rows_scanned 명시
- 표시는 항상 **'예시값'**: "전체 값의 분포나 품질을 대표하지 않습니다" 문구 고정

## 6. 수집 파이프라인

```
후보 선정 → 다운로드 → (ZIP 해제·시트 열거) → 테이블별 스캔(유형·카운트·bottom-k 후보)
→ 안전 스크리닝 → 라이선스 게이트 → [통과한 값만] 불변 관측 저장 + CoverageState 갱신
```

**저장 원칙**: 예시값 후보는 스캔 중 메모리에만 존재하며, 안전·라이선스 판정을 통과한
값만 영구 저장한다. 거부된 후보는 폐기하고 example_status로 사유만 남긴다 —
검사 전 원본 값이 디스크에 남지 않는다.

- 예절: 동시 1~2 연결, 요청 간격, 야간 배치, 식별 가능한 UA, 재시도 상한, 중단 창구
- **커버리지 웨이브(실측 기반)**: W1 표준데이터(300)+국가중점 FILE(~4천) →
  W2 다운로드 1,000+(20,067건) → W3 수요 기반
- **W3는 비동기 큐(지적 12)**: 사용 로그는 수집을 직접 트리거하지 않는다 —
  수요 점수 누적 → 중복 제거 → 라이선스·크기·포맷·제외 목록 검사 → 야간 배치 큐.
  화면 표기: "데이터 구조 미수집 — 수요 기반 관측 대상에 등록됨"
- 재수집: 목록 `modified_date` 변경 시 재방문. 해시 동일 → 기존 관측 불변,
  `last_verified_at`만 갱신. 해시 변경 → 새 관측 생성, structure_hash 비교로
  스키마 변경 이력 기록(S2)

## 7. 안전·라이선스 통제 (지적 9·10·11)

  포함된 URL은 **저장 자체를 금지**
- README "실데이터 재배포 없음" 문구를 "라이선스가 허용하는 범위의 컬럼별 예시값 발췌
  제공"으로 개정 + §10 고지문에 신고·비공개 절차 추가

## 부록 A. 관측 입력 계약 (Structure Ingest v1 — 초안)

외부 제공자(수동 정리, 별도 수집기, 기관 제공 스키마)가 파일별 컬럼·예시값을 공급할 때의
입력 형식. **NDJSON — 한 줄 = SourceAsset 1개의 관측 1건.** 서버는 이를 검증·게이트 통과
후 §3 모델(SourceAsset→Observation→DataTable→FileColumn)로 적재한다.

### A.1 정본 형식 (JSON, 자산 단위)

```jsonc
{
  "listKey": "15012345",                 // 필수 — 카탈로그 연결 키(존재 검증)
  "listType": "FILE",                    // 필수
  "asset": {
    "fileName": "시설현황_2026.csv",       // 필수
    "format": "CSV",                     // 필수: CSV|XLSX|ZIP|...
    "portalUrl": "https://www.data.go.kr/...",  // 권장
    "sourceSha256": "ab34…",             // 강력 권장 — 없으면 재현성 약화(A.4)
    "sizeBytes": 1234567                 // 선택
  },
  "observedAt": "2026-07-29T10:00:00Z",  // 필수 — 관측(파일 확인) 시점
  "toolVersion": "collector/0.1.0",      // 필수 — 수동이면 "manual/이름"
  "tables": [                            // 필수 ≥1 — CSV는 1개, XLSX는 시트별
    {
      "sheetName": null,                 // XLSX면 필수, CSV는 null
      "sourcePath": null,                // ZIP 멤버면 내부 경로 필수
      "tableIndex": 0,                   // 필수 — 파일 내 순번(0-base)
      "scanScope": "FULL",               // 필수: FULL|PARTIAL
      "rowsScanned": 1520,               // 필수 — 모든 카운트의 분모
      "rowCountTotal": 1520,             // 알면(모르면 생략)
      "encoding": "UTF-8",               // CSV 권장
      "delimiter": ",",                  // CSV 권장
      "columns": [                       // 필수 ≥1, ordinal 유일·1부터 연속
        {
          "ordinal": 1,                          // 필수
          "sourceName": "시설명",                 // 필수 — 원본 그대로(공백·오탈자 포함)
          "observedType": "STRING",              // 선택: INTEGER|NUMBER|STRING|DATE_LIKE|BOOL_LIKE|EMPTY
          "examples": ["중앙경로당", "행복경로당"], // 선택 ≤10 — 원본 문자열 그대로, 가공 금지
          "exampleMethod": "HASH_BOTTOM_K_DISTINCT", // examples 제공 시 필수:
                                                     // HASH_BOTTOM_K_DISTINCT|DISTINCT_UP_TO_10|FIRST_ROWS|MANUAL
          "nullCountObserved": 3,                // 선택 — 분모는 rowsScanned
          "emptyStringCountObserved": 0          // 선택
        }
      ]
    }
  ]
}
```

### A.2 최소 유효 입력 (이것만 있어도 적재 가능)

```json
{ "listKey": "15012345", "listType": "FILE",
  "asset": { "fileName": "시설현황.csv", "format": "CSV" },
  "observedAt": "2026-07-29T10:00:00Z", "toolVersion": "manual/hklab",
  "tables": [ { "tableIndex": 0, "scanScope": "PARTIAL", "rowsScanned": 0,
    "columns": [ { "ordinal": 1, "sourceName": "시설명" },
                 { "ordinal": 2, "sourceName": "소재지도로명주소" } ] } ] }
```
→ 컬럼 존재·순서만 확보(예시값·유형 없음). example_status는 NOT_COLLECTED로 산출된다.

### A.3 서버가 하는 일 (제공자가 하지 않아도 되는 것)

| 처리 | 내용 |
|---|---|
| 검증 | listKey 카탈로그 존재, ordinal 유일·연속, examples ≤10·문자열, enum 검사. 실패 행은 사유와 함께 거부 목록으로 반환 |
| 안전 스크리닝 | **제공된 예시값에도 `sample-safety-v1.0` 전면 적용** — 통과분만 저장, 거부분 폐기 + example_status=WITHHELD_BY_SAFETY. 입력 신뢰와 무관하게 우회 불가 |
| 라이선스 게이트 | 카탈로그의 license_code로 판정 — OTHER면 예시값 저장 안 함(WITHHELD_BY_LICENSE) |
| ID·상태 부여 | observation_id 결정식 계산, Asset/RecordCoverageState 갱신(성공/PARTIAL 집계) |
| 유형 보완 | observedType 미제공 시 예시값 기반 약식 관측(있을 때만) 또는 미기재로 둠 |

### A.4 재현성 등급 (입력 품질을 그대로 노출)

제공 방식의 한계는 고치지 않고 **기록해서 노출**한다:
- `sourceSha256` 없음 → 관측에 `provenance: "UNVERIFIED_SOURCE"` — 화면·Tool에 표시
- `exampleMethod: FIRST_ROWS|MANUAL` → 그대로 기록(HASH_BOTTOM_K로 위장 금지),
  warnings에 "표본 방법상 값 다양성이 제한될 수 있음" 동반
- `rowsScanned: 0`(미상) → 카운트류 필드 전부 무효 처리

### A.5 표 형식 대안 (수동 정리용 — 서버가 A.1로 변환)

스프레드시트/CSV로 정리할 경우 1행 = 1컬럼:

```
listKey, fileName, sheetName, ordinal, sourceName, observedType, example1..example10, exampleMethod, rowsScanned, scanScope
```
변환기가 (listKey, fileName, sheetName) 그룹을 자산·테이블로 묶는다. 병합 셀·수식 금지,
예시값 셀은 텍스트 서식 고정(선행 0 보존).

### A.6 실물 입력 검토 (2026-07-30 — 데이터_프로파일_260729.xlsx / 프로파일_컬럼별.csv)

외부 정리 실물을 검토한 결과 **재작성 불필요 — 이 형식을 정본 입력의 제1 지원 형식으로
채택**하고 어댑터가 A.1로 변환한다. 필드 매핑:

| 제공 열 | Ingest v1 대응 | 비고 |
|---|---|---|
