# 데이터 구조 관측 계층 설계 v2.1 (초안)

- 상태: DRAFT v2.1 (2026-07-29) — v2 초안에 대한 2차 검토(15개 지적) 전면 반영
- 위상: 설계서 v1.0(동결)의 **확장 계층** — 3층 구조·책임 분리(§2)·식별자 체계(§7)를
  변경하지 않으며, 계약은 부속 명세 semver(minor)로 처리한다. **재개봉 불필요.**
- 선행 관계: v1.0 공개 배포(MCP 스택)와 독립 — 배포를 차단하지 않는 별도 트랙
- 개정 이력: v2(초안) → v2.1 — 2차 검토의 필수 4건(모델 계층·상태 분리·추출 방식·
  스캔 범위)과 권고 6건 반영. 판정표는 §0.1 참조

## 1. 목표와 비목표

**목표** — 사용자가 포털에서 파일을 내려받기 전에 답할 수 있게 한다:
"이 데이터에 필요한 컬럼이 실제로 존재하고, 값이 예상한 형식인가?"

**비목표(명시적으로 하지 않음)** — 컬럼 의미 동일성 판정, 실제 조인 가능성 판정,
전체 데이터 품질 평가, 컬럼 정규화·표준 매핑(후속 별도 계층).

**근거 수준 사다리 확장**: `CATALOG_METADATA_ONLY`(현행) → **`FILE_OBSERVATION`**(신규,
파일 구조·예시값 범위 — scan_scope로 FULL/PARTIAL 강도 구분) → `API_RESPONSE_SAMPLE`(3차).
신규 수준은 **신규 표면에만** 쓰며 기존 응답의 evidenceLevel은 불변.

## 3. 데이터 모델 (v2.1 개정 — 필수 지적 1·2·3·5·6·8·9 반영)

**핵심 정정**: CatalogRecord는 특정 시점의 목록 기술 레코드이지 실제 파일이 아니다.
하나의 FILE 목록에 CSV·XLSX 복수 파일, 연도별 파일, ZIP 내부 다수 파일, XLSX 다중 시트가
있을 수 있으므로 컬럼은 **실제 관측한 파일의 테이블**에 귀속한다.

```
Dataset (기존, 불변)
 └─ CatalogRecord (기존, 불변)
     ├─ StructureCoverageState (신규, 가변 1행) ← 레코드별 현재 수집 상태
     └─ SourceAsset (신규: 실제 파일 1개)
         └─ StructureObservation (신규: 특정 파일 버전의 불변 관측)
             ├─ DataTable 1 (CSV 본문 / XLSX 시트 / ZIP 멤버)
             │   └─ FileColumn[]
             └─ DataTable 2
                 └─ FileColumn[]
```

관측 스토어는 카탈로그 릴리스와 분리한다(`data/observations/observations.db`).
월간 목록 스냅샷과 파일 관측은 주기·수명이 다르며, 연결 키는 (목록키, list_type)이다.

### StructureCoverageState (가변 — 상태 머신, 관측이 아님)
```
record_id, list_key, list_type
coverage_status        NOT_COLLECTED | QUEUED | COLLECTING | AVAILABLE | PARTIAL
                       | SOURCE_UNAVAILABLE | UNSUPPORTED_FORMAT | ACCESS_RESTRICTED
                       | COLLECTION_FAILED | API_STRUCTURE_NOT_SUPPORTED_YET
reason                 상태 사유(기계 판독 코드)
last_attempt_at        마지막 시도 시점
current_observation_id 최신 관측 참조(AVAILABLE·PARTIAL일 때만)
portal_url             공개 포털 상세 페이지
```
미수집·실패는 **여기까지만** 기록된다 — 해시·컬럼 없는 "관측"은 존재하지 않는다.

### SourceAsset (실제 파일)
```
asset_id               결정 ID
record_id
file_name, format      CSV | XLSX | ZIP | ...
portal_url             공개 가능 — MCP 응답 기본값
source_locator         내부 수집용 실제 위치(서명 URL·토큰 가능성) — 비공개 저장
source_locator_public  boolean — 안전 확인된 경우에만 응답 포함
```

### StructureObservation (불변 — 파일을 실제 분석한 경우에만 생성)
```
observation_id   = sha256(asset_id + source_sha256 + tool_version + rule_bundle_version)
                   — 같은 파일이라도 규칙·도구가 바뀌면 새 관측
source_sha256    파일 해시(재현성 앵커)
observed_at      최초 관측 시점 — 이후 절대 변경하지 않음
last_verified_at 동일 해시 재확인 시점 — 재수집 시 이것만 갱신
tool_version, rule_versions
scan_scope       FULL | PARTIAL      ← 유형·결측 판정의 분모 명시(지적 6)
rows_scanned     스캔 행 수
structure_hash   테이블·컬럼 구조의 해시(스키마 변경 이력의 비교 키)
license_gate     FULL | COLUMNS_ONLY (S0-2 게이트 결과)
```

### DataTable (지적 2 — XLSX 시트·ZIP 멤버 구분)
```
table_id, observation_id
source_path            ZIP 내부 경로(해당 시)
sheet_name             XLSX 시트명(해당 시)
table_index            파일 내 순번
row_count_observed, column_count
encoding, delimiter    (CSV)
```

### FileColumn
```
ordinal                원본 순서 (1-base, 테이블 내)
source_name            원본 컬럼명 — 절대 변경하지 않음
observed_type          INTEGER|NUMBER|STRING|DATE_LIKE|BOOL_LIKE|EMPTY
type_observation       { scan_scope, values_examined, non_empty_examined, rule }
examples[]             예시값 ≤10 (license_gate=FULL이고 안전 판정 통과 시에만)
example_method         HASH_BOTTOM_K_DISTINCT (§5)
null_count_observed    스캔 범위 내 결측 수 (분모 = rows_scanned)   ← 지적 5
empty_string_count_observed / placeholder_count_observed
sample_safety_status   CLEAR | MASKED | WITHHELD | REVIEW_REQUIRED | NOT_ASSESSED  ← 지적 10
safety_reason          PII | LICENSE | FREE_TEXT | TECHNICAL (WITHHELD·REVIEW 시)
format_note            제한적 관찰("YYYY-MM-DD 형태" 등) — 없을 수 있음
-- AIRD 예약(v2에서는 산출·표시하지 않음, 지적 14):
distinct_count_observed?, distinct_count_method?, parse_failure_count?
```

## 4. 관측 사실과 규칙 기반 판정의 구분 (지적 7)

> 원본 컬럼명·순서·파일 해시·포맷·관측 시점·행/컬럼 수·예시값의 원본 문자열은
> **직접 관측 사실**로 기록한다. `observed_type`, `sample_safety_status`, `format_note`,
> placeholder 추정, 라이선스 게이트 결과는 **명시된 규칙에 의해 생성된 관찰·판정**이며
> 해당 규칙 버전을 동반한다.

| ruleId | 내용 |
|---|---|
| `column-type-observation-v1.0` | 스캔 범위 기반 유형 관측 — scan_scope·분모 동반 필수 |
| `example-extraction-v1.0` | **HASH_BOTTOM_K_DISTINCT** (§5) — 첫 10행·정렬 상위 방식 금지 |
| `sample-safety-v1.0` | 위험군별 기본 처리(§7 표) — 컬럼명 사전 + 값 패턴 이중 탐지 |
| `structure-status-v1.0` | CoverageState 상태 전이 규칙 |

## 5. 예시값 추출 — 해시 bottom-k (지적 4)

```
값을 원본 문자열로 보존 → 스트리밍 스캔 → h = hash(column_id + raw_value)
→ (h, value) 최소 10개만 유지(중복 값은 동일 해시로 자기 자신과만 경합)
```

- 결정론적(재실행 동일), 메모리 O(10), 행 순서 독립, 사전순·크기순 편향 없음
- 전량 스캔이 전제이므로 null/empty/placeholder 카운트도 같은 패스에서 정확히 계산
- 대용량 상한(예: 500MB) 초과 시 scan_scope=PARTIAL + rows_scanned 명시
- 표시는 항상 **'예시값'**: "전체 값의 분포나 품질을 대표하지 않습니다" 문구 고정

## 6. 수집 파이프라인

```
후보 선정 → 다운로드 → (ZIP 해제·시트 열거) → 테이블별 스캔(유형·카운트·bottom-k)
→ 안전 스크리닝 → 라이선스 게이트 → 불변 관측 저장 + CoverageState 갱신
```

- 예절: 동시 1~2 연결, 요청 간격, 야간 배치, 식별 가능한 UA, 재시도 상한, 중단 창구
- **커버리지 웨이브(실측 기반)**: W1 표준데이터(300)+국가중점 FILE(~4천) →
  W2 다운로드 1,000+(20,067건) → W3 수요 기반
- **W3는 비동기 큐(지적 12)**: 사용 로그는 수집을 직접 트리거하지 않는다 —
  수요 점수 누적 → 중복 제거 → 라이선스·크기·포맷·제외 목록 검사 → 야간 배치 큐.
  화면 표기: "데이터 구조 미수집 — 수요 기반 관측 대상에 등록됨"
- 재수집: 목록 `modified_date` 변경 시 재방문. 해시 동일 → 기존 관측 불변,
  `last_verified_at`만 갱신. 해시 변경 → 새 관측 생성, structure_hash 비교로
  스키마 변경 이력 기록(S2)

## 7. 안전·라이선스 통제 (지적 9·10·11)

**위험군별 기본 처리** (`sample-safety-v1.0`):

| 위험군 | 기본 처리 |
|---|---|
| 주민번호·계좌·개인 전화·이메일 | WITHHELD |
| 차량번호·자격번호·개인 상세주소 | WITHHELD 또는 REVIEW_REQUIRED |
| 시설명·기관명·시설 주소 | 문맥 규칙으로 CLEAR 가능 (일률 차단 금지 — 서비스 가치 보존) |
| 기관 대표전화 | MASKED (정책 확정 시 CLEAR 가능) |
| 코드·분류·날짜 | CLEAR |
| 자유서술 | REVIEW_REQUIRED |

- 예시값은 검색 인덱스에 넣지 않는다(컬럼명만 FTS — S2)
- **긴급 대응은 SLA가 아니라 메커니즘으로(지적 11)**: 데이터셋 단위 즉시 비공개 스위치 +
  예시값 전체 비활성화 플래그 + "신고 접수 시 해당 예시값을 우선 비공개하고 검토한다"
  (처리 목표시간은 운영 가능성이 확인된 후에만 고지)
- URL 통제(지적 9): 응답 기본은 `portal_url`. `source_locator`는 내부 저장 전용이며
  서명·토큰 포함 가능성이 있으므로 공개 플래그 확인 후에만 노출. API 단계에서 인증키가
  포함된 URL은 **저장 자체를 금지**
- README "실데이터 재배포 없음" 문구를 "라이선스가 허용하는 범위의 컬럼별 예시값 발췌
  제공"으로 개정 + §10 고지문에 신고·비공개 절차 추가

## 8. 표면 설계

- 프로필 "데이터 구조" 탭: 테이블(시트)별 컬럼 표 + 관측 출처·범위 + 면책 문구,

### 정본 URI (지적 13 — 버전화)
```
/projects/datanav/record/{recordId}/structure/current        → 최신 관측(303 또는 표현)
```

정본화(JSON-LD·PROV)는 안정화 후.

## 9. 단계 계획과 수용 기준 (지적 15 — 일정 표현 정정)

| 단계 | 범위 | 수용 기준 |
|---|---|---|
| **S0** 선행 조사 | §2의 3건 | 확보 경로·법적 게이트 문서화. 미충족 시 표준데이터 300으로 축소 |
| **S1** 관측 코어 | 수집기+관측 스토어+`get_dataset_structure`+구조 탭, W1 | 동일 파일→동일 관측(결정론), 안전 스크리닝 표본 검사 100건, 커버리지 표기, 계약 v1.2 라이브 검증, 기존 테스트 전건 불변 통과 |
| **S2** 활용 점검 | 컬럼 검색(커버리지 명시)+구조 비교+메타 대조+스키마 변경 이력 | 검색 결과에 근거·커버리지 필수 표기, 골든셋에 컬럼 질의 축 추가 |
| **S3** API 구조 | 오퍼레이션·요청/응답 모델 | DOCUMENTED/OBSERVED 상태, 키 비저장, 호출 조건 기록 |

**일정 표현**: 수집기·스토어의 내부 프로토타입은 집중 작업 수일 규모로 예상한다.
안전·라이선스 검토, W1 수집(포털 예절 속도 종속), MCP·웹 공개 표면과 수용 검사를
포함한 **공개 배포 일정은 S0 결과와 실제 수집 성공률 확인 후 산정**한다.

## 10. AIRD 연계 (지적 14 — 표현 축소)

> 파일 구조 관측은 **D7-02 기술적 유효성 등 구조·파싱 관련 지표**의 실측 원천이 될 수 있다.
> 결측·유일성(D6-01) 지표는 전체 또는 규정된 표본 범위의 별도 측정값이 확보된 경우에
> 한하여 활용한다.

보완 각주: v2.1의 추출 방식이 전량 스캔을 전제하므로 결측 카운트는 정확값이 확보되며,
distinct는 근사 방법(HyperLogLog 등)을 `distinct_count_method`와 함께 **예약 필드**로만
둔다 — v2에서는 산출·표시하지 않고, 개별 AIRD 진단·DM 부여는 표본·규칙 검증 후의
별도 결정으로 남긴다.
