# 정규화 매핑표 v1.0

설계서 §9의 공개 산출물. 원본(목록개방현황 CSV) → 정규화 필드 → JSON-LD 속성 매핑.
모든 정규화는 판정 규칙 레지스트리의 규칙 버전으로 관리된다(`/api/resources/rules`).

## 1. 컬럼 매핑

| 원본 컬럼 | 정규화 필드 | JSON-LD | 비고 |
|---|---|---|---|
| 목록키 | `list_key` | `dct:identifier`, `kdp:listKey` | 레코드 식별의 기초 |
| 목록유형 | `list_type` | `kdp:listType` | FILE / API / STD |
| 목록명 | `title` | `dct:title` | |
| 파일데이터명 | `file_data_name` | — | FILE 프로파일 완전성 평가 대상 |
| 분류체계 | `theme_raw` → `theme_top`/`theme_sub` | `dcat:theme` | " - " 구분자 분리 |
| 제공기관코드/제공기관 | `org_code`/`org_name` | `dct:publisher` | |
| 관리부서 전화번호 | `dept_phone` | — | 백틱 접두어 제거(원본은 source 뷰 보존, 이슈 관찰) |
| 업데이트 주기 | `update_cycle_raw` → `update_cycle` | `dct:accrualPeriodicity`(원본) | normalize-cycle-v1.0 |
| 전체행/다운로드/조회수 | `row_count`/`download_count`/`view_count` | — | 정수화, 실패 시 null + 이슈 관찰 |
| 확장자(데이터포맷) | `format_raw` → `formats[]` | — | normalize-format-v1.0, `+` 분리·대문자화 |
| 키워드 | `keywords[]` | `dcat:keyword` | 쉼표 분리·중복 제거 |
| 등록일/수정일 | `created_date`/`modified_date` | `dct:issued`/`dct:modified` | |
| 데이터 한계/설명/기타 유의사항 | `data_limits`/`description`/`notes` | `dct:description`(설명) | `-` → null |
| 공간범위/시간범위 | `spatial_raw`/`temporal_raw` | `dct:spatial`/`dct:temporal` | region-match-v1.0의 1차 근거 |
| 비용부과유무 | `fee` | — | FREE/PAID/UNSPECIFIED/OTHER |
| 이용허락범위 | `license_raw` → `license_code` | `dct:license`(원본) | normalize-license-v1.0 |
| API 유형/신청가능 트래픽 | `api_type`/`traffic` | — | API 프로파일 평가 대상 |
| 목록 URL | `list_url` | `dcat:landingPage` | 100% 보존(수용 기준) |
| 국가중점여부/표준데이터여부 | `is_national_core`/`is_standard` | — | Y/N → 1/0 |

값 규칙: 공백·`-`·`null`·`없음`은 미기재(null)로 정규화한다. 원본 행 전체는 `source_json`으로 무손실 보존한다.

## 2. 레코드 식별 (record-identity-v1.0)

- 원칙: `record_id` = 목록키.
- 동일 목록키가 복수 목록유형(FILE/API)으로 등재된 경우(2026-02 스냅샷 기준 22건):
  두 행 모두 보존하고 `record_id` = `{목록키}-{목록유형}`, `DUPLICATE_LIST_KEY` 이슈 관찰 생성.
- 수용 기준 "목록키 중복 0"은 "정규화 후 record_id 중복 0"으로 판정하며,
  원본의 중복은 §6 이슈 관찰로 표면화한다(원본 불변).

## 3. 코드 사전

- **update_cycle**: 수시→IRREGULAR, 일간→DAILY, 주간→WEEKLY, 월간→MONTHLY, 분기→QUARTERLY, 반기→SEMIANNUAL, 연간→ANNUAL, `-`→UNSPECIFIED, 그 외→OTHER
- **license_code**: 이용허락범위 제한 없음→NO_RESTRICTION, 공공저작물_출처표시→KOGL_BY, +상업적 이용금지→KOGL_BY_NC, +변경금지→KOGL_BY_ND, +상업적 이용금지+변경금지→KOGL_BY_NC_ND, 저작자표시-비영리-동일조건변경허락→CC_BY_NC_SA, `-`→UNSPECIFIED, 그 외→OTHER
  ※ 표기 정규화일 뿐 법적 해석이 아니다. 원문 확인 필요.
- **region**: 시·도 17개, ISO 3166-2:KR 코드. 근거 수준 EXPLICIT_SPATIAL(0.95) > INFERRED_FROM_TITLE(0.8) > INFERRED_FROM_PUBLISHER(0.6) > INFERRED_FROM_DESCRIPTION(0.5). 동음이의 별칭(광주 등)은 0.3 감점.

## 4. 완전성 프로파일 (§3.2)

`catalogMetadataCompleteness` = 프로파일별 평가 필드 중 기재된 필드 비율.

- **FILE**(16필드): 공통 13 + format, row_count, file_data_name
- **API**(15필드): 공통 13 + api_type, traffic — 파일 전용 필드를 감점하지 않음
- **STD**(12필드): 공통 축소 + format

공통 13: title, theme, org_name, update_cycle, keywords, description, license, created_date, modified_date, list_url, spatial, temporal, data_limits
